# 改稿ノート(レビュー用)

原案から変えた点と、その根拠(適用スキル)。

## 構成

- **冒頭を「タブレットで見た言い争い」という具体の場面に差し替えた**。原案の「ずっと不思議に思っていた」は抽象的な状態の説明で、緊張の材料が状況側にない。具体の言い争いを置くことで、シーン3(ワーキングメモリ)とシーン5(多軸の適用)で同じ場面に二度着地でき、全編を貫く具体になる(cognitive-rhythm: 拍・緊張の材料は状況側から取る/結びは読者が持っている具体へ着地)
- **シーン1の末尾で「理由は少なくとも三つある」と列挙の緊張を開いた**。以後、円を一つ閉じるたびに残りが気になる構造。「少なくとも」としたのは、最終カットの「心」(=第四の何か)への伏線を論理的に破綻させないため(japanese-tech-writing: 検出・保証を「必ず」と書かない)
- **シーン7-5の問いを「違うのが当たり前なら、なぜそれでも争うのか」に強化した**。原案の「どうして争いはなくならないんでしょう」は本編の内容と独立に成立してしまう。本編の結論(違いは構造的で当たり前)を前提に踏んだ問いにすることで、回収と次への緊張を同時にやる

## セリフ

- **ミケの即答「頑張ることです。決まってます」(2-2)**: あとで崩される思い込みを、先に自信として言い切らせた(cognitive-rhythm: 逡巡は仕掛け。裏切られる確信は布石)
- **「ずるです」(2-5)**: 辞書の違いを定義の並記で終わらせず、感情的な対立(すれ違いの実感)に着地させた(列挙の着地)
- **2-6「使っている言葉が同じだから、違っていることに気づけない」**: 原案は「辞書は一匹ずつ違う」で止まっていた。すれ違いが解消されない機構を一文添えた(japanese-tech-writing: 因果には機構を示す)
- **3-4のミケの発見**: 認知能力の列挙を、冒頭の言い争いの観察に着地させた。「処理速度」「ワーキングメモリ」などの術語は、音声で聞き取りにくいため黒板表記ごと和語に開いた(「覚えたまま考えられる量」)。読み手(視聴者)の負荷管理
- **3-6「どちらが偉いという話ではない」**: 能力差の話が優劣の話に誤読される展開を明示的に処理(japanese-tech-writing: 読者が立てそうな誤った解釈は明示的に否定する)
- **4-3「見ているのは世界そのものではなく、自分の地図のほうだ」**: 原案の「今日、一番伝えたいのは」という予告型の前置きを削除し、主張をそのまま言わせた(LLM口調の排除: 「重要なのは〜」型の禁止)
- **5-6「載っていない場所の話は、間違いに聞こえる」**: 「だから議論はすれ違う」の前に機構を一段挟んだ。地図が違う→すれ違う、の間の飛躍を埋める
- **6-3の器の比喩**: 原案の「認知能力は器にすぎない」を保持しつつ、「注ぐものがなければ軸は増えない」で比喩を最後まで使い切り、6-4以降の列挙(中身)と6-5(眺め直す力)に橋を架けた
- **6-4のミケの先走り「じゃあ、経験を積めば」**: 列挙を受け身で聞かせず、誤った一般化を先にミケに言わせてから訂正する形にした。「振り返らない経験は同じ軸を濃くするだけ」が訂正の機構
- **「メタ認知」の導入(6-5)**: 原案では黒板に突然書かれる。改稿では「眺め直す力」という働きを先に述べ、そのあと命名する順にした(japanese-tech-writing: 辞書型断定で始めず、導入→働き→定義の順/cognitive-rhythm: 理論は答えではなく命名として入れる)
